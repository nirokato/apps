What Bubble Share is

Bubble Share is a small Android app by Simon Gougeon (s1m, of UnifiedPush) that shares files, text and links to the phone next to you. It is an alternative to AirDrop, Quick Share and Nearby Share built on Wi-Fi Aware: no internet, no shared network, no QR code. You pick a device from the share sheet and both phones show the same six-digit pairing code.

  • License AGPL-3.0 · Kotlin + Jetpack Compose · Android 10+ (minSdk 29, targetSdk 37) · v0.1.2 at the time of writing
  • Transports Wi-Fi Aware by default, Wi-Fi Direct as an NFC-negotiated fallback, and NFC tap for pairing or for handing a link to any phone
  • Identity an X25519 key pair per device, sealed in the Android Keystore; peers see a name and an 8-hex-digit id, and you can rotate it from Settings

This page is an unofficial showcase. Every byte it displays comes from a JavaScript re-implementation of the app's protocol pieces (protocol.mjs), checked against RFC and library test vectors. Nothing leaves your browser.

    How a share works

    1Advertise. The receiver's app publish()es the Wi-Fi Aware service fr.s1m.share with a CBOR blob: device name, X25519 public key, and whether it accepts files. The sender's share sheet subscribe()s, and also publishes an informative copy with r = false so the receiver's "Nearby devices" list shows the sender too. 2Connect. Tapping a peer sends one Wi-Fi Aware L2 message (≤255 bytes): Connect{name, nonce, pubKey, kind, nFiles}. Both sides compute HMAC-SHA256(X25519 shared secret, "NONCE:" ‖ nonce) and derive the Wi-Fi passphrase and the pairing code from it. 3Consent. Each phone shows the same six digits in an Accept / Refuse dialog with a 30 s timeout. Nothing else is compared, so the code is the whole anti-MITM story: if the digits differ, somebody is in the middle. 4Data path. The receiver opens a ServerSocket, requests a TRANSPORT_WIFI_AWARE network with WifiAwareNetworkSpecifier(peer).setPskPassphrase(psk).setPort(port), and echoes the Connect. The sender requests the matching network, reads the peer's IPv6 and port from WifiAwareNetworkInfo, and opens one TCP socket per file. The receiver only accepts that IPv6. 5Stream. Each socket carries one frame: FILE_V1 (opcode, name, 64-bit size, bytes) or TEXT_V1. Files land in Downloads/BubbleShare through MediaStore; a length mismatch deletes the partial file. URLs open an app picker, other text opens the system share sheet.

    Lab · The six-digit code

    Two throwaway identities, a fresh nonce, and the exact key schedule from Crypto.kt, computed here with X25519 and HMAC-SHA256. Both columns must agree.

    Device id = "%08x".format(pubKey.contentHashCode()) over the 44-byte X.509 encoding of the public key. Pairing code = |Arrays.hashCode(HMAC(msk, "PAIRING_CODE"))| mod 10⁶. The Wi-Fi passphrase is Base64url(HMAC(msk, "WIFI_PSK")); TLS_KEY_ID and TLS_PSK feed the PSK-TLS session used over Wi-Fi Direct.

    Lab · Bytes on the wire

    What the sender actually writes. Type some text, or pick a local file to see its FILE_V1 header (only the name and size are read, nothing is uploaded).

    The discovery blobs

    kotlinx.serialization CBOR with its defaults: indefinite-length maps, byte arrays as arrays of signed integers, default-valued fields omitted. The Connect message must fit a Wi-Fi Aware message (255 bytes), which caps how long a device name can be.

    Lab · The NFC tap

    While the share sheet is open, the sender emulates an NFC Type-4 tag (HostApduService). A reader sees two applications on it.

    Requirements and caveats

    • Android 10 or newer with Wi-Fi Aware hardware. Wi-Fi must be on; on Android 12 and older, location too. A running hotspot, or another app holding Wi-Fi Direct, makes Aware unavailable on many devices.
    • Permissions: NEARBY_WIFI_DEVICES (declared neverForLocation), ACCESS_FINE_LOCATION up to API 32, ACCESS_LOCAL_NETWORK on API 37, notifications, NFC.
    • Early version: the author warns that a future release may break compatibility, especially to get iOS support. Refusing a pairing is not yet signalled to the peer; it just times out.
    • Received files go to Downloads/BubbleShare; the OS picks the MIME type, so duplicates get the usual (1) suffix before the extension.

    Compared with the usual suspects

    • AirDrop / Quick Share are built in, cross-pollinate on Pixel 10, and are closed. Bubble Share is AGPL and reads the same way on any Android 10+ phone with Aware.
    • LocalSend needs both devices on one LAN and uses HTTPS with a PIN. Bubble Share forms its own link over Aware, so it works where there is no network at all.
    • Trebleshot, Warpinator and friends also assume a shared network or a QR / hotspot dance. The pitch here is "no network, no QR, six digits".
